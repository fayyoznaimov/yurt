# Сборщик скидок → сайт-каталог

Программа собирает товары из магазинов: со скидкой из Турции и подборки с YOOX (например, футболки известных брендов за 50–70 €). Отбирает те, что подходят под ваши фильтры, пересчитывает цену в сумы с вашей маржой и обновляет сайт-каталог.

## Запуск

```bash
python run.py
```

Через несколько минут откройте `site/index.html`.

- Режим владельца: `site/index.html?admin=1`. В нём видны себестоимость, маржа и ссылка на товар в магазине, а также сводки по источникам и брендам (берутся из `products-admin.js` по коду товара).
- Пересчитать цены без захода на сайты (например, после смены маржи или фильтров): `python run.py --offline`.
- Обновить один источник: `python run.py --only trendyol`. Для YOOX: `python run.py --only yoox_import`.

В конце `run.py` печатает сводку. По каждому источнику видно, сколько товаров подошло из собранного. По брендам печатаются 25 самых крупных, остальные одной строкой «…ещё N брендов». Дальше — сколько карточек получили цвет, состав и пункты описания, и самые частые **непереведённые** значения (цвета, волокна, свойства) — их стоит добавить в словари `describe.py`.

## Что настраивается в `config.json`

Ключи, которые начинаются с `_` (например `_help`), — пояснения, программа их не читает.

| Поле | Что это |
|---|---|
| `sources` | какие источники использовать: `pcardin_tr`, `cacharel_tr`, `trendyol`, `yoox_import` (YOOX через кнопку) |
| `filters.brands` | бренды; пусто — все. Пробелы и знаки не важны: `Dolce & Gabbana` = `Dolce&Gabbana` |
| `filters.types` | типы: `обувь`, `сумки`, `рубашки`, `футболки и поло`, `толстовки`, `свитеры и кардиганы`, `куртки и пальто`, `пиджаки и костюмы`, `брюки`, `джинсы`, `шорты`, `платья`, `юбки`, `нижнее бельё`, `аксессуары`; пусто — все |
| `filters.genders` | `men`, `women`; пусто — все |
| `filters.discount_min` | минимальная скидка, %. `0` — брать и товары без скидки |
| `filters.price_min` / `price_max` | цена в магазине, **в валюте магазина**: евро для YOOX, лиры для Турции. Пусто или `0` у `price_max` — без ограничения |
| `filters.price_uzs_min` / `price_uzs_max` | диапазон цены продажи в сумах |
| `filters.only_with_sizes` | показывать только товары с известными размерами |
| `source_filters` | свои фильтры для одного источника, поверх `filters` (см. ниже) |
| `pricing.margin_pct` | ваша маржа, % |
| `pricing.min_margin_uzs` | минимальная маржа в сумах с одной вещи |
| `pricing.fx_markup_pct` | на сколько % вы покупаете валюту дороже курса ЦБ |
| `pricing.cargo_uzs_per_item` | доставка одной вещи до Ташкента: `TR` из Турции, `IT` из Италии |
| `pricing.fx_manual` | ручной курс, например `{"TRY": 245}`; пусто — курс ЦБ (cbu.uz) |
| `crawl.max_pages` | сколько страниц распродажи смотреть в каждом разделе (для всех источников) |
| `source_opts.<источник>.max_pages` | то же для одного источника, важнее `crawl.max_pages`. Например, `pcardin_tr.max_pages: 10` |
| `source_opts.trendyol.brand_slugs` | адрес бренда на Trendyol: откройте бренд на trendyol.com и скопируйте конец ссылки, например `pierre-cardin-x-b122` |
| `source_opts.trendyol.pdp_limit` | у скольких товаров Trendyol уточнять размеры (каждый товар — отдельная страница) |
| `source_opts.yoox_import` | YOOX: поиски для кнопки, бренды, фото (см. раздел про YOOX) |
| `site.contact_url` | **ваша ссылка в Telegram**, на неё ведёт кнопка «Заказать» (если в `site/content.json` не задан `contacts.telegram`) |
| `site.name`, `site.tagline` | название магазина для логотипа и подпись под ним, если они не заданы в `site/content.json` (по умолчанию `YURT`) |

### Свои фильтры для источника: `source_filters`

У турецких распродаж нужна большая скидка, а с YOOX вы берёте вещи известных брендов в диапазоне цены, даже без скидки. Для этого в `source_filters` задаются фильтры одного источника. Они заменяют те же поля из `filters`, остальные поля берутся из `filters`.

```json
"filters": { "brands": ["Pierre Cardin", "Cacharel"], "discount_min": 40, "price_uzs_max": 5000000, "only_with_sizes": true },
"source_filters": {
  "yoox": { "brands": [], "discount_min": 0, "price_min": 0, "price_max": 1000, "price_uzs_max": 50000000 }
}
```

Здесь для YOOX: бренды любые (их уже выбрала кнопка на YOOX), скидка не нужна, цена на YOOX до 1000 €, цена продажи до 50 млн сум. Размеры обязательны, как в `filters`. Для Турции действуют `filters`: только Pierre Cardin и Cacharel со скидкой от 40%.

Ключ в `source_filters` — источник товара: `yoox` (это и `yoox_import`), `pcardin_tr`, `cacharel_tr`, `trendyol`.

### Как считается цена

Цена продажи = (цена × курс ЦБ × (1 + наценка на курс) + доставка). К этой сумме прибавляется маржа: процент или минимальная, что больше. Результат округляется вверх до `round_to_uzs`.

## Источники

| Источник | Статус |
|---|---|
| Pierre Cardin Турция (раздел Garage Sale) | работает, обычные запросы |
| Cacharel Турция (разделы Outlet и «Online'a Özel») | работает, только мужская одежда |
| Trendyol | работает; размеры уточняются только у первых `pdp_limit` товаров |
| YOOX (`yoox_import`) | работает **через кнопку-закладку** (см. ниже) |
| YOOX автоматически (`yoox`) | выключен: YOOX блокирует браузер, которым управляет программа, и без окна, и с окном. Защиту не обходим |

Если один источник сломается или его заблокируют, программа напишет «ВНИМАНИЕ: источник не обновился», возьмёт его прошлые данные (`data/raw_<источник>.json`) и продолжит с остальными: товары этого источника с сайта не пропадают. Подробнее — в разделе «Слежение за наличием».

## YOOX через кнопку «Сохранить YOOX»

YOOX не пускает программы, но открывается в вашем Chrome. Поэтому товары с YOOX собирает кнопка-закладка: она работает на открытой вами странице YOOX и сохраняет товары в файл `yoox_….json` в «Загрузки». Потом `run.py` берёт эти файлы.

### Один раз: сделать кнопку

1. Запустите `python make_button.py`. Он возьмёт ваши поиски и бренды из `config.json` и соберёт страницу `yoox-knopka.html`.
2. Откройте `yoox-knopka.html` в Chrome и перетащите синюю кнопку на панель закладок (панели не видно — `Ctrl+Shift+B`).

**Поменяли `searches` или `known_brands`?** Снова запустите `python make_button.py`, откройте `yoox-knopka.html`, удалите старую закладку и перетащите кнопку заново. Закладка помнит поиски, которые были в момент перетаскивания.

### Каждый раз: собрать товары

Откройте любую страницу каталога YOOX, например `yoox.com/it/uomo/shoponline/t-shirt_c`, нажмите закладку и выберите режим:

- **1 — все мои поиски.** Кнопка по очереди откроет каждый поиск из `searches`. В каждом она отметит ваши бренды, поставит цену и сортировку и пролистает все страницы. Это то же, что вы делали руками: категория, известные бренды, «сначала дешёвые», 50–70 €.
- **2 — только эта выдача.** Сначала сами поставьте фильтры на YOOX: бренды, цену, сортировку. Потом нажмите кнопку, и она сохранит все страницы этой выдачи.

Между страницами кнопка ждёт 3–6 секунд, чтобы не нагружать YOOX. Если в одном поиске случилась ошибка, кнопка бросает этот поиск и переходит к следующему. Если YOOX ответил «слишком часто» или «доступ запрещён» (HTTP 403, 429, 503), сбор останавливается целиком. Кнопка «Стоп» останавливает сбор после текущей страницы. В любом случае собранное сохраняется.

Кнопка проверяет, что YOOX действительно применил фильтр брендов. Если среди товаров меньше 80% нужных брендов, такая выдача пропускается, чтобы не сохранить всю категорию.

В итоге кнопка покажет, сколько товаров собрано в каждом поиске и каких брендов на YOOX не нашлось. Редких брендов (1–2 вещи в категории) может не быть: YOOX показывает только 350 самых частых.

Потом запустите `python run.py` (или `python run.py --only yoox_import`). Товары YOOX пройдут фильтры `filters` + `source_filters.yoox` и получат цену в сумах. В одном файле могут быть и женские, и мужские поиски: раздел определяется у каждой страницы. Если товар есть в нескольких файлах, берётся самый новый файл.

### Настройки `source_opts.yoox_import`

| Поле | Что это |
|---|---|
| `searches` | поиски для режима 1: `name` — название, `url` — адрес категории на YOOX, `brands` — `"known"` (все из `known_brands`), свой список `["Boss", "Hugo"]` или `"url"` (ссылка как есть). Если `brands` не указан: для страницы бренда (`…/tombolini_d`) или ссылки, где бренды уже отмечены, берётся `"url"`, иначе `"known"`. `price` — `[от, до]` в евро, `sort` — `"PriceAsc"` (сначала дешёвые), `"BestDeals"` (лучшие скидки), `"Latest"` (новинки) |
| `known_brands` | известные бренды для `brands: "known"`; так же они пишутся на сайте (`EA7`, а не `Ea7`) |
| `max_pages_per_search` | сколько страниц по 60 товаров брать в одном поиске (YOOX отдаёт не больше 200) |
| `max_total_pages` | сколько страниц кнопка открывает за одно нажатие, по умолчанию 80 |
| `folder` | где искать файлы `yoox_*.json`; пусто — «Загрузки». Путь пишите через `/`, например `"D:/Загрузки"` (обратную черту `\` в JSON нужно удваивать) |
| `max_age_days` | файлы старше этого числа дней не берутся (по умолчанию 3): цены и наличие на YOOX быстро меняются |
| `download_images` | скачивать ли фото в `site/img/yoox/` |
| `max_images` | сколько новых фото скачать за один запуск (главное фото товара; сначала товары с большей скидкой, потом дешёвые). Уже скачанные фото используются всегда и лимит не тратят. Остальные фото товара (до 8 ракурсов) и фото остальных товаров показываются по ссылке с yoox.com |

Пример поиска:

```json
{ "name": "Поло мужские, 50–80 €", "url": "https://www.yoox.com/it/uomo/shoponline/polo_c",
  "brands": "known", "price": [50, 80], "sort": "PriceAsc" }
```

## Сайт

Сайт — один файл `site/index.html`, сборка не нужна. Разделы (адрес после `#` можно присылать покупателю):

| Адрес | Что там |
|---|---|
| `#/` | главная: объявление, герой с кнопкой в каталог, категории с фото, «Новинки», бренды, «Лучшие скидки», «До 1 000 000 сум», ленты по крупным категориям, «Почему нам доверяют», «Как заказать», частые вопросы |
| `#/catalog?type=брюки&brand=Boss` | каталог с фильтрами. Параметры: `brand`, `type`, `size`, `for`, `from` / `to` (цена), `disc`, `sort` (`new`, `asc`, `desc`, `brand`), `q` (поиск), `sold=1`. Старые ссылки вида `#brand=Boss&p=КОД` тоже работают |
| `#/brands` | все бренды по алфавиту |
| `#/about`, `#/delivery`, `#/payment`, `#/returns`, `#/contacts`, `#/faq`, `#/sizes` | страницы для покупателя: тексты из `content.json`, таблицы размеров |
| `…?p=КОД` (на любом адресе) | карточка товара поверх страницы. «Поделиться» даёт ссылку `#/?p=КОД` |

В карточке товара, кроме фото, размеров, заказа и кода:
- **«Таблица размеров»** рядом с размерами. Таблица выбирается по типу вещи и системе размеров: одежда (INT / IT / RU / UK-US, грудь и талия), рубашки по вороту, брюки (IT / W), джинсы (W, L), обувь (EU / UK / US / длина стопы, в том числе 40 ⅔). Размеры этой вещи, которые есть в наличии, подсвечены. Внизу кнопка «Написать нам» с готовым текстом: «помогите с размером, код …».
- **Доставка и оплата / Обмен и возврат / Гарантия оригинальности** — раскрывающиеся блоки с текстами из `content.json`.
- **«С этим носят»** — вещи других категорий, которые сочетаются с этой: к брюкам — рубашки, поло, свитеры, пиджаки, обувь; к рубашкам — брюки, пиджаки, джинсы; к обуви — брюки и джинсы и т. д. (правила — `WEAR_WITH` в `index.html`). Только в наличии; выше вещи того же бренда и близкой цены.
- **«Похожие»** — та же категория, цена ±30% (если мало — ±60%), не больше 3 вещей одного бренда. **«Ещё от бренда»** — другие вещи бренда и ссылка на все.

Ленты на главной меняются раз в сутки. «Новинки» — по дате, когда товар впервые появился на сайте (поле `first_seen`). Пока все товары появились в один запуск, порядок в ленте случайный, но постоянный в течение дня.

### Тексты продавца: `site/content.json`

Всё, что пишет продавец, лежит в `site/content.json`: название и подпись под логотипом, полоса объявления, заголовок и текст главной, «О нас», доставка, оплата, возврат, оригинальность, шаги «Как заказать», контакты, частые вопросы. Файл можно открыть в Блокноте.

- Меняйте только текст в кавычках справа от двоеточия. Кавычку `"` внутри текста не ставьте, пишите «ёлочки».
- Абзацы разделяются `\n\n`, перенос строки — `\n`. Строка, которая начинается с `- `, становится пунктом списка.
- Первый абзац текстов `delivery`, `payment`, `returns` и `authenticity` виден на главной в блоке «Почему нам доверяют». Весь текст — на отдельной странице и в карточке товара.
- Пустое поле `""` скрывает блок. Если убрать поле совсем, сайт покажет текст по умолчанию.
- `contacts.telegram` — ваш ник (`@shop`, `shop` или `https://t.me/shop`). Если он задан, кнопки «Заказать» и «Написать» ведут туда. Если пусто — на `site.contact_url` из `config.json`. `instagram`, `phone`, `address`, `hours` показываются в подвале и на странице «Контакты»; пустые не показываются.
- Пока стоит `"_draft": true`, в режиме `?admin=1` сверху висит напоминание, что тексты — черновик. Тексты по умолчанию — образец: сроки, способы оплаты и условия возврата замените своими. Когда закончите, поставьте `"_draft": false`.

После правки запустите `python content.py`: он проверит файл (при ошибке назовёт строку) и обновит `site/content.js`. Этот файл нужен, чтобы тексты были видны и при открытии `index.html` двойным щелчком. `python run.py` и `python deploy.py` делают это сами. На хостинге страница читает и сам `content.json`, поэтому правка видна сразу после выкладки.

**Название и логотип.** Логотип — знак «тундук» (верх юрты) и название буквами. Название берётся из `name` в `content.json`, если там пусто — из `site.name` в `config.json`, если и там нет — `YURT`. Подпись рядом с логотипом — `tagline`. Значок вкладки браузера — тот же знак.

### Каталог

- Товары без скидки показываются без значка скидки. В фильтре «Скидка» по умолчанию «Любая», при сортировке «По скидке» такие товары идут в конце.
- Если брендов больше 15, список брендов свёрнут: видны самые крупные и выбранные, остальные — по ссылке «Ещё N брендов» или через поиск «Найти бренд». Enter в поиске выбирает бренд, если найден один.
- Товары показываются по 48, дальше — кнопка «Показать ещё». Каталог на 3000 товаров фильтруется без задержек.

## Слежение за наличием и автообновление

Каждый запуск `run.py` сравнивается с прошлым (память — `data/state.json`):

- **Товар распродан** — он ещё `sync.keep_sold_out_days` дней (по умолчанию 3) остаётся на сайте с пометкой «Нет в наличии»: серое фото, вместо кнопки заказа — неактивная «Нет в наличии». По умолчанию такие товары скрыты; покупатель видит их, включив в фильтрах «Показать распроданные». Прямая ссылка на такой товар открывает карточку с «Нет в наличии». Потом товар исчезает.
- **Размер закончился** — на сайте он зачёркнут («Размер закончился») рядом с размерами в наличии (поле `sizes_out` в `products.js`: размеры, которые были за последние 14 дней, а теперь нет). Фильтр по размеру ищет только размеры в наличии.
- **Что изменилось** — `run.py` печатает сводку (новые, распроданные, вернувшиеся, закончившиеся размеры, цены) с примерами, подробно — `data/changes/ГГГГММДД_ччмм.json`.

Когда товар считается распроданным (осторожно: не уверены — не помечаем):

- **Турция (Pierre Cardin, Cacharel, Trendyol).** Программа смотрит только первые страницы распродажи, поэтому «нет в выдаче» ещё не значит «продан». Такие товары (и товары, у которых в выдаче нет размеров) перепроверяются по ссылке на их страницу — до `sync.verify_limit` (120) за запуск. Распроданным считается товар, если страница ответила 404 или показала, что в наличии ничего нет. Не удалось проверить — товар остаётся как был (не дольше 7 дней с последней проверки).
- **YOOX** перепроверить нельзя, поэтому товар считается пропавшим, только если его нет в самом новом файле кнопки, поиск которого точно его охватывал: страница бренда (`…/boss_d`) того же раздела, цена товара в диапазоне поиска, и поиск пролистан до конца или (сортировка «сначала дешёвые») товар дешевле последнего собранного. Поиски по категориям ничего не доказывают. Нового файла нет — товары YOOX остаются как были.
- **Сбой источника.** Ошибка или блокировка — берутся прошлые данные. Блокировка посреди обхода или вдруг на `sync.max_drop_pct` (50%) товаров меньше, чем в прошлый раз, — новые данные берутся, а пропавшие из выдачи товары остаются. Если распродажа правда закончилась: `python run.py --only pcardin_tr --accept-drop`.

Несколько источников сразу: `python run.py --only pcardin_tr,cacharel_tr,trendyol`. Два `run.py` одновременно не работают: второй ждёт первого (замок `data/run.lock`).

### Обновление по расписанию: `update.py`

`python update.py` — один проход: собирает Pierre Cardin, Cacharel и Trendyol, а YOOX — только если в «Загрузках» есть новый файл `yoox_*.json` (новее прошлого импорта). Если `sync.auto_deploy` = `true`, после этого выкладывает сайт (`deploy.py`); по умолчанию `false` — выкладываете сами. Журнал каждого прохода — `data/logs/update_ГГГГММДД_ччмм.log` (хранятся 30 дней). Замок `data/update.lock` не даёт двум проходам идти одновременно.

Запуск каждые `sync.every_hours` часов (по умолчанию 6) — одна команда для Планировщика заданий Windows. Её печатает:

```bash
python update.py --print-schedule
```

Сейчас это:

```
schtasks /Create /TN "YooxDeals Update" /TR "C:\Users\Asus\AppData\Local\Programs\Python\Python312\pythonw.exe C:\Users\Asus\projects\yoox-deals\update.py" /SC HOURLY /MO 6 /ST 07:00 /F
```

Выполните её в «Командной строке» или PowerShell (без прав администратора). Задание запускается, пока вы вошли в Windows, без окна (`pythonw.exe`). Проверить сразу: `schtasks /Run /TN "YooxDeals Update"`, удалить: `schtasks /Delete /TN "YooxDeals Update" /F`. Поменяли `every_hours` — снова напечатайте и выполните команду (`/F` заменит задание).

| Поле `sync` | Что это |
|---|---|
| `keep_sold_out_days` | сколько дней распроданный товар виден с пометкой «Нет в наличии» |
| `auto_deploy` | выкладывать ли сайт после `update.py` |
| `every_hours` | как часто запускать `update.py` (для `--print-schedule`) |
| `max_drop_pct` | на сколько % меньше товаров считать сбоем источника |
| `verify_limit` | сколько товаров перепроверять по ссылке за запуск (каждый — запрос с паузой 1,5–3,5 с) |

Служебные файлы в `data/`: `state.json` (память), `sold_out.json` (карточки распроданных), `raw_<источник>.meta.json` (как прошёл сбор), `changes/`, `logs/`.

Планировщик Windows работает, только пока включён ваш компьютер. Чтобы каталог обновлялся сам, без вас, — раздел «Работа без вашего компьютера» ниже. **Если включаете сервер, удалите задание на компьютере** (`schtasks /Delete /TN "YooxDeals Update" /F`): иначе сайт будут публиковать двое.

## Работа без вашего компьютера

| Вариант | Что нужно | Что делает сам | Что остаётся вам |
|---|---|---|---|
| **Свой сервер (Linux)** — основной | сервер Ubuntu/Debian с SSH и sudo | каждые 6 ч Турция → сайт; каждые 15 мин — новые файлы YOOX; в 09:00 — курс ЦБ; уборка; уведомления | нажать кнопку YOOX и `python push_yoox.py` |
| GitHub Actions — запасной | только GitHub | каждые 6 ч Турция → сайт | кнопка YOOX и `python push_yoox.py --github` |

YOOX ни сервер, ни GitHub сами не собирают: YOOX закрыт защитой от программ, обходить её мы не будем. Товары YOOX приходят только из файлов вашей кнопки (или, в будущем, из официального партнёрского фида — `sources/feed_yoox.py`, см. ниже). Пока новых файлов нет, товары YOOX остаются на сайте как были.

### Свой сервер (Linux)

Всё ставится в `/opt/yurt` под отдельным пользователем `yurt`: `app/` — код и `data/`, `venv/` — Python, `inbox/` — «входящие» для файлов YOOX. Настройки и секреты — `/etc/yurt/yurt.env` (не в git).

**1. Доступ к GitHub для публикации.** Сервер выкладывает сайт в ветку `gh-pages`, для этого ему нужен доступ на запись. Выберите одно:

- **Deploy key (рекомендуется)** — ключ только для этого репозитория, без срока. Ничего заранее делать не нужно: на шаге 2 запустите установку с `DEPLOY_KEY=generate`, она покажет строку `ssh-ed25519 …`. Её вставьте: GitHub → репозиторий `yurt` → Settings → Deploy keys → Add deploy key, Title `yurt-server`, галочка **Allow write access** → Add key.
- **Fine-grained токен.** GitHub → ваш профиль → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token: Repository access — Only select repositories → `yurt`; Permissions → Repository permissions → **Contents: Read and write**; срок — до года (поставьте себе напоминание продлить). Скопируйте токен и на сервере сохраните в файл: `sudo sh -c 'umask 077; cat > /root/gh_token'`, вставьте, Enter, Ctrl+D. На шаге 2 добавьте `GH_TOKEN_FILE=/root/gh_token`.

**2. Установка** (на сервере; можно повторять — обновит, ничего не сломает):

```bash
git clone https://github.com/fayyoznaimov/yurt.git /tmp/yurt
sudo DEPLOY_KEY=generate bash /tmp/yurt/server/setup.sh          # или: sudo GH_TOKEN_FILE=/root/gh_token bash …
```

Скрипт ставит python3/git, создаёт пользователя `yurt`, клонирует репозиторий в `/opt/yurt/app`, ставит `requests` в `/opt/yurt/venv`, создаёт `/etc/yurt/yurt.env` и включает таймеры systemd.

**3. Ваш компьютер → «входящие» сервера** (по ключу SSH, пароли не используются). На компьютере, в папке проекта:

```bash
python push_yoox.py --setup yurt@АДРЕС_СЕРВЕРА        # порт не 22 — добавьте --port 2222
```

Он создаст ключ `~/.ssh/yurt_ed25519` и покажет строку `ssh-ed25519 … yurt push_yoox`. На сервере сохраните её в `/root/pc.pub` (`sudo nano /root/pc.pub`) и выполните `sudo OWNER_PUBKEY_FILE=/root/pc.pub bash /opt/yurt/app/server/setup.sh`. Проверка с компьютера: `python push_yoox.py --check`.

**4. Перенос текущих данных** (один раз, чтобы сервер помнил, что уже было на сайте, и сразу показывал товары YOOX): `python push_yoox.py --migrate`.

**5. Первый сбор:** `sudo systemctl start yurt-job@update.service`, смотреть ход: `journalctl -u yurt-job@update -f` (10–25 минут). Сайт обновится на GitHub Pages через 1–2 минуты после конца.

**6. Уведомления в Telegram (по желанию).** В Telegram откройте @BotFather → `/newbot` → получите токен. Напишите своему боту любое сообщение, откройте в браузере `https://api.telegram.org/bot<токен>/getUpdates` и найдите `"chat":{"id": …}` — это ваш chat id. На сервере: `sudo nano /etc/yurt/yurt.env`, впишите `TELEGRAM_BOT_TOKEN=…` и `TELEGRAM_CHAT_ID=…`. Проверка: `sudo -u yurt bash -c 'set -a; . /etc/yurt/yurt.env; cd /opt/yurt/app && $YURT_PYTHON notify.py --test'`. Бот пишет, когда задание упало, когда источник сломался или не обновлялся больше 30 часов (`YURT_STALE_HOURS`) и когда снова заработал — без повторов каждые 15 минут.

**Каждый день:** нажали кнопку «Сохранить YOOX» → `python push_yoox.py`. Файлы уйдут во «входящие», сервер сразу импортирует их и выложит сайт (без `--no-run` — не ждать). Если не запустить — сервер сам заберёт их в течение 15 минут.

**Что работает по расписанию** (время ташкентское; `systemctl list-timers 'yurt-*'`):

| Таймер | Когда | Что делает (`server/yurt-run.sh …`) |
|---|---|---|
| `yurt-update.timer` | 00:05, 06:05, 12:05, 18:05 | `git pull` (ваши правки `config.json` / `index.html` на GitHub подхватываются сами), Турция (`update.py`), сборка, публикация, проверка источников |
| `yurt-yoox.timer` | каждые 15 минут | если во «входящих» есть новый `yoox_*.json` — импорт, сборка, публикация; нет — сразу выходит |
| `yurt-fx.timer` | 09:00 | пересчёт цен по свежему курсу ЦБ (`run.py --offline`), публикация |
| `yurt-cleanup.timer` | воскресенье 04:30 | удаляет журналы старше 30 дней, файлы «входящих» старше 14 дней, фото ушедших товаров YOOX старше 30 дней (`server/cleanup.py`) |

Задания никогда не идут одновременно (замок `data/server.lock`), сайт публикуется, только если правда изменился. Журналы: `journalctl -u 'yurt-job@*' --since today` и `/opt/yurt/app/data/logs/`. Без systemd — то же через cron: `server/crontab.example`. Выключить всё: `sudo systemctl disable --now yurt-update.timer yurt-yoox.timer yurt-fx.timer yurt-cleanup.timer`.

| В `/etc/yurt/yurt.env` | Что это |
|---|---|
| `YURT_YOOX_FOLDER` | «входящие» для файлов YOOX (важнее `source_opts.yoox_import.folder`) |
| `YURT_AUTO_PULL` | `1` — перед заданием update брать свежий код и настройки из GitHub |
| `YURT_DEPLOY` | `1` — публиковать сайт; `0` — только собирать |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | уведомления; пусто — без уведомлений |
| `TZ` | `Asia/Tashkent`: дата курса ЦБ и время «Обновлено» на сайте |

**Если сервер вне Турции и Trendyol/магазины его не пускают** — ничего не ломается: источник получает статус «не обновился», на сайте остаются прошлые товары, бот пишет об этом. Проверить с сервера: `sudo -u yurt bash -c 'cd /opt/yurt/app && /opt/yurt/venv/bin/python run.py --only trendyol'`.

### GitHub Actions (запасной вариант, без сервера)

Файл `.github/workflows/update.yml`: машина GitHub каждые 6 часов собирает Турцию, пересобирает сайт и выкладывает его в `gh-pages`. Память между запусками (`data/state.json`, `data/raw_*.json`, `products-admin.js`…) хранится в ветке `data` **зашифрованной** (`datastore.py`): репозиторий публичный, а там ссылки на магазины и закупочные цены. Не включайте одновременно с сервером.

1. Ключ шифрования: `python datastore.py init-key` (файл `~/.yurt/data_key.txt`). GitHub → репозиторий → Settings → Secrets and variables → Actions → New repository secret: Name `DATA_KEY`, Secret — строка из этого файла. По желанию там же `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.
2. Первая память: `python push_yoox.py --github --seed --no-import` — создаёт ветку `data` из данных этого компьютера.
3. Settings → Actions → General: Actions разрешены (Allow all actions). Settings → Pages: источник — ветка `gh-pages`, папка `/ (root)` (как сейчас).
4. Расписание: Settings → Secrets and variables → Actions → вкладка Variables → New repository variable `RUN_IN_ACTIONS` = `true`. Без неё workflow запускается только вручную: Actions → «Каталог: обновление» → Run workflow (там же режим `offline` — только пересобрать сайт, и «принять падение числа товаров»).
5. YOOX: после кнопки — `python push_yoox.py --github`: берёт память из ветки `data`, импортирует файлы, записывает память обратно и сразу публикует сайт (вместе с новыми фото).

Правки `config.json` / `site/index.html` в ветке `main` пересобирают сайт сами (режим offline). Итог запуска — в сводке запуска на вкладке Actions (таблица источников). Риски: машины GitHub — адреса Microsoft Azure в США, Trendyol (Cloudflare) может их не пустить — тогда Trendyol «не обновился», на сайте прошлые товары. В публичном репозитории GitHub отключает расписание после 60 дней без активности; последний шаг workflow включает его заново, но раз в пару месяцев загляните во вкладку Actions. Проверка файла workflow на компьютере: `python tests/check_workflow.py`.

### Партнёрские фиды (официальные данные YOOX/Trendyol) — что выяснилось

Проверено 3 октября 2026 по открытым страницам:

- **YOOX** ведёт партнёрскую программу сам: витрины Италия/Великобритания/Германия/Франция — через **Partnerize** (`join.partnerize.com/yoox`, ссылка со страниц `yoox.com/<страна>/affiliation/registration`), витрина США — через **Rakuten Advertising** (`yoox.com/us/affiliation/program`). На Awin программы YOOX закрыты. YOOX обещает партнёрам ежедневный фид товаров (и XML-каталог по запросу); какие в нём поля (размеры, наличие, цена до скидки) — видно только после одобрения. Контакт: affiliation@yoox.com.
- **Trendyol**: профиль на Awin (25550, это была Германия) неактивен, остальные сетевые программы закрыты; программа для блогеров (influencer.trendyol.com) — без Узбекистана и от 30 тыс. подписчиков; API Trendyol — только для продавцов. Официального фида для нас нет.
- **Главное ограничение:** условия партнёрских сетей разрешают показывать данные фида только чтобы отправлять покупателя в магазин (он покупает сам, вы получаете комиссию 3–11%). Перепродажа с наценкой в сумах под это не подходит, а правила продажи YOOX — только для конечных покупателей. Покупки по своей же партнёрской ссылке комиссии не дают.
- **Выплаты в Узбекистан:** у Rakuten — только PayPal/чек (PayPal в Узбекистане не работает); Partnerize и Awin заявляют выплаты по всему миру, но Узбекистан прямо не назван — уточнять до регистрации.

Если формат «каталог со ссылками на YOOX» подходит — заявка в Partnerize, а фид подключается адаптером `sources/feed_yoox.py`: `"sources": [..., "feed_yoox"]` вместо `yoox_import`, ссылка на фид — в переменной окружения `YOOX_FEED_URL` (на сервере — `/etc/yurt/yurt.env`; в ссылке ваш ключ, в публичный `config.json` её не пишем), свои имена колонок — `source_opts.feed_yoox.columns`. Проверка адаптера: `python tests/test_feed_yoox.py`.

## Карточка товара: что видит покупатель

Покупатель не должен видеть, из какого магазина вещь. Поэтому `run.py` пишет два набора данных:

- **`products.js` / `products.json` (публичные)** — у товара только поля: `id`, `brand`, `title`, `type`, `gender`, `origin` (`"IT"` / `"TR"`), `price_uzs`, `discount_pct`, `sizes` (в наличии), `sizes_out` (закончились), `size_system`, `color`, `composition`, `details`, `description`, `images`, `in_stock`, `fetched_at`, `first_seen` (когда товар впервые появился на сайте). В `summary` — дата, общая сводка и сводка по брендам. Магазинов, ссылок, исходных названий, валюты, закупочной цены и маржи там нет.
- **`products-admin.js` (только для вас)** — `window.DEALS_ADMIN = {"<id>": {source, source_item_id, url, title_original, category_original, price_now, price_old, currency, cost_uzs, margin_uzs}, "_meta": {rates, by_source, filters}}`.

**Код товара `id`** — 7 символов, например `XZXUTRY`: начало base32(sha1(«источник:номер товара»)). Он не меняется между запусками и ничего не говорит о магазине. Клиент называет код — вы находите товар в `?admin=1` или в `products-admin.js`.

**Фото.** Адаптеры хранят до 8 фото товара (все ракурсы YOOX, все фото Pierre Cardin / Cacharel / Trendyol). Скачанные фото YOOX копируются для сайта в `site/img/p/<код>-<n>.jpg`, чтобы в адресе не было ни имени магазина, ни его номера товара. Остальные фото пока показываются по ссылкам с CDN магазинов (yoox.com, akinoncloudcdn.com, dsmcdn.com) — по адресу картинки внимательный покупатель может догадаться об источнике.

**`size_system`**: `EU` — обувь, `INT` — S/M/L, `W` — джинсы и брюки по талии (дюймы), `IT` / `EU` — числовые итальянские / турецкие размеры одежды, `null` — безразмерные или непонятные.

### Тексты: `describe.py`

Адаптеры сохраняют сырые свойства товара в `attrs` (`data/raw_*.json`): у YOOX — состав, цвет, материал, сезон, категории, `dynamicAttributes`; у Pierre Cardin / Cacharel — крой, воротник, рукав, узор, состав, сезон; у Trendyol — свойства со страницы товара («Materyal», «Kalıp», «Yaka Tipi», «Kol Boyu», «Desen»…; только у первых `pdp_limit` товаров). `describe.py` переводит их на русский:

- `title` — «Рубашка Barba Napoli», «Мокасины Tod's», «Женские брюки Pierre Cardin» (словари `KIND_RULES` / `KIND_DEFAULT`);
- `color` — `COLORS` (итальянские и турецкие названия → русские);
- `composition` — `FIBRES`: «95% Cotone, 5% Elastan» и «%95 Pamuk %5 Elastan» → «95% хлопок, 5% эластан»;
- `details` — пункты «Приталенный крой (slim fit)», «Воротник-поло», «Короткий рукав»…: `TOPIC_KEYS` (какое свойство о чём) и `TOPIC_VALUES` (перевод значений), плюс подсказки из категорий YOOX и турецких названий;
- `description` — 1–3 предложения из всего этого и «Оригинал. Привезём из Италии/Турции.»

Чего нет в словарях, на сайт не попадает (никакого итальянского/турецкого текста), а `run.py` печатает это в конце. Чтобы добавить перевод, допишите пару «как на сайте» → «по-русски» в нужный словарь (регистр и турецкие/итальянские буквы не важны) и запустите `python run.py --offline`.

## Что выкладывать на хостинг

Из папки `site/` выкладываются: `index.html`, `products.js`, `products.json`, `content.js`, `content.json`, `img/p/`. Папку `img/yoox/` выкладывать не нужно: в ней имена файлов по номерам YOOX, сайт берёт копии из `img/p/`.

**Не выкладывайте `products-admin.js`.** В нём ссылки на магазины, себестоимость и маржа, он нужен только вам для режима `?admin=1`.
